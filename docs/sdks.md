# SDK packaging

The four clients under `clients/` are generated by janus from the
contract and regenerate through the golden test; they are single
files with no hand-written siblings. The packages that ship them are
assembled, and the assembly is the pipeline:

```
sdks/
  VERSION            one version for all four, e.g. 0.1.0
  rust/              Cargo.toml skeleton  -> crate oneiriq-copal (lib name copal)
  python/            pyproject skeleton   -> package oneiriq-copal (module copal)
  typescript/        package.json + tsconfig -> @oneiriq/copal
  go/                go.mod               -> github.com/Oneiriq/copal-go
  build.sh           assemble into sdks/dist and validate all four
```

`bash sdks/build.sh` copies each generated client into its skeleton
under `sdks/dist/<language>`, stamps the version from `sdks/VERSION`,
and validates: `cargo check`, `py_compile` plus an import, `tsc
--noEmit`, `go build` and `go vet`. CI runs the same script on every
push, so a client that stops compiling in any language fails the PR
that broke it. That check is what caught the first real bug here: the
generated Python had never been compiled by anything until this
pipeline existed.

Publishing is a separate, manually dispatched workflow
(`publish-sdks.yml`) that dry-runs by default. Bumping `VERSION` and
dispatching with `dry_run: false` is the whole release motion once
registry tokens exist; until then the workflow proves the packages
build and stops there. Go versions by tag on a mirror repo rather
than a registry write, and the workflow prints the tag to cut.
